# Decision log

Every non-obvious decision made while building the research repository, newest at the bottom. Each entry says what was decided and why. Spec reference: "Internal Research Repository: Spec v0.1" (Oct 15, 2026).

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-10-15 | Project lives at `~/Projects/heyMarvinClone`; Personal project; private GitHub repo `exidium/researchRepo` | Bruno's choice. The Google Drive project convention path does not exist on this Mac. |
| D2 | 2026-10-15 | Next.js 16 app router + TypeScript; Prisma 7 as ORM (not Drizzle). Prisma pinned to `^7.10` because npm `latest` is an 8.0 release candidate | Same stack as the sibling project `theyDoClone`; known patterns; one codebase for frontend and API. |
| D3 | 2026-10-15 | Tailwind 4 + shadcn/ui (base-nova, Base UI), zod, nuqs, vitest, playwright | Copied from the sibling project so the two apps feel and build the same way. |
| D4 | 2026-10-15 | Local development uses Homebrew Postgres 17 (database `research`). Docker Compose is only for the Hetzner deployment | Docker is not installed on the dev Mac. |
| D5 | 2026-10-15 | Highlights anchor to `(segmentId, characterOffset)` pairs, never to offsets in the whole transcript | Spec requirement: fixing a typo in one line must not shift highlights elsewhere. |
| D6 | 2026-10-15 | The transcript editor forbids splitting, merging or deleting segments in v1. Only text and speaker edits are allowed | Keeps highlight anchors stable; split/merge is the hardest edge case and not needed for v1. |
| D7 | 2026-10-15 | Search uses Postgres full-text search: generated `tsvector` columns on Segment and Highlight with GIN indexes, `websearch_to_tsquery`, `ts_headline`, queried via Prisma `$queryRaw`. `pg_trgm` index as an ILIKE fallback for exact phrases and non-English text | Spec says built-in FTS covers v1. Prisma's own `search` filter cannot rank or combine with the four-table filters. |
| D8 | 2026-10-15 | Seed data is a generated **synthetic** mirror in `fixtures/mirror/`, in the same folder and JSON shape as the Dovetail mirror, plus an importer that reads that shape | Bruno asked for mock data, not the confidential ADI export. The same importer can ingest the real mirror later by pointing `MIRROR_DIR` at it; real content never enters the repo. |
| D9 | 2026-10-15 | The auth and role seam (`getCurrentUser`, `requireProjectRole`, `projectAction`) exists from the first milestone; real email+password login is the last milestone | Spec: login is one of the last things. Role checks must not be retrofitted into every action later. |
| D10 | 2026-10-15 | Files are stored on server disk under `UPLOAD_DIR/sources/<sourceId>/`. The original transcript file is kept. Recordings are stored as uploaded; no ffmpeg transcoding in v1 | Spec. ffmpeg is only needed for v2 clips and is not installed locally. |
| D11 | 2026-10-15 | Tags are global. `TagGroup` is its own table so groups can be renamed and reordered. Tag names are unique case-insensitively | Spec: "manage the global tag list: groups, rename, merge, archive". |
| D12 | 2026-10-15 | No `proxy.ts` (the Next 16 replacement for middleware) in v1 | Next 16 buffers request bodies through the proxy and silently truncates them at 10 MB, which would corrupt uploads. Auth gating lives in the app layout and the action seam instead. |
| D13 | 2026-10-15 | Uploads are raw-body `PUT` route handlers that stream to disk through a byte limiter. Never server actions (1 MB body cap) or `request.formData()` (buffers the whole file in memory) | Recordings can be gigabytes. |
| D14 | 2026-10-15 | `cacheComponents` stays off. Pages are dynamic. `revalidatePath` runs after CRUD mutations but never during per-segment transcript saves | The app is per-user and dynamic; a re-render while typing would be disruptive. |
| D15 | 2026-10-15 | Permissions: `User.isAdmin` manages users, tag groups, tag rename/merge/archive and deletions. Any editor can create a tag while highlighting. OPEN projects give everyone VIEWER. RESTRICTED projects are hidden from lists and search unless the user is a member. A project's owner is ADMIN of that project | Spec roles table plus the open question answers: admin deletes participant data; tag list owned by admin, tag creation by user type. |
| D16 | 2026-10-15 | Search tag filter is ANY-of by default with an ALL toggle. Product area is free text with autocomplete, not an enum | Simple and matches Dovetail habits; an enum can come later if the list stabilises. |
| D17 | 2026-10-15 | Highlight colour comes from the tag group of its first tag (neutral fallback). Overlapping highlights are allowed and render nested | Dovetail-like readability. |
| D18 | 2026-10-15 | VTT and SRT cues are coalesced into utterance-sized segments (same speaker, gap under 2 s, until a sentence ends and about 200 characters). DOCX and Dovetail paragraphs are not coalesced | Per-cue segments of a few words make highlighting painful. |
| D19 | 2026-10-15 | A highlight whose text is deleted entirely becomes `ORPHANED` (kept, shown greyed in the side panel), never silently dropped. Undo restores it | Evidence must not vanish because of a typo fix. |
| D20 | 2026-10-15 | Re-uploading a transcript is blocked once the source has highlights; delete and recreate the source instead | A re-parse would replace all segments and orphan every highlight. |
| D21 | 2026-10-15 | The `AUTH_DISABLED` dev seam refuses to run when `NODE_ENV=production`. Sessions are opaque tokens (sha256 stored) in an HttpOnly cookie, 30 days; passwords hashed with argon2 | Safety and simplicity; the seam can be swapped for company SSO later. |
| D22 | 2026-10-15 | Any signed-in user can create a project and becomes its owner (project ADMIN). Global admins can delete projects; owners can archive them. Any user can create or edit participants; only global admins delete them | Roles are per project, so there is no global "editor" flag to gate creation on. The spec's "editor creates projects" maps to "anyone can start a study". |
| D23 | 2026-10-15 | Editors can delete a source only while it has no highlights; project admins can delete any source | Protects tagged evidence from accidental deletion while keeping uploads easy to redo. |
| D24 | 2026-10-15 | Project edit, members and archive live in dialogs on the project page, not a separate settings route | Fewer routes; everything about a project is one screen. |
| D25 | 2026-10-15 | The selection toolbar is our own absolutely positioned element driven by `editor.view.coordsAtPos`, not TipTap's BubbleMenu | Fewer moving parts and no floating-ui behaviour to debug; the toolbar only needs to sit above the selection start. |
| D26 | 2026-10-15 | `Highlight.text` is always the transcript slice its anchors cover (joined with newlines across segments); it is rebuilt on every segment save. Only ORPHANED highlights keep their last text | One source of truth for search and display; the importer follows the same rule. |
| D27 | 2026-10-15 | Segment node views are plain DOM, not React, and the editor never rebuilds its document after mount; all changes flow through ProseMirror transactions, with a `skipSave` meta for programmatic ones (marks, speaker renames) | A two-hour transcript has thousands of segments; React node views and document rebuilds would be too slow and would fight the user's caret. |
| D28 | 2026-10-15 | Per-segment saves are debounced 600 ms and carry an optimistic `version`; a stale version returns an error that asks for a reload (last writer loses) | Simple concurrency story for a small team; no CRDT in v1. |
| D29 | 2026-10-15 | Tag merge is one SQL insert-select with `ON CONFLICT DO NOTHING` into the target, then the source tag is deleted (cascading its old links). The source's Dovetail ids move to the target's `externalIds` | A highlight tagged with both ends up tagged once; re-importing the mirror still maps the old tag id to the merged tag. |
| D30 | 2026-10-15 | Deleting a group keeps its tags (they become ungrouped). Deleting a tag removes it from all highlights and is admin-only; the UI steers towards archiving | Archive is reversible and keeps history; delete is for mistakes. |
| D31 | 2026-10-15 | Search is English full-text only in v1 (`websearch_to_tsquery('english')`, so quotes make a phrase and `-word` excludes). No ILIKE fallback yet; the `pg_trgm` index is in place for when non-English transcripts arrive | Keeps every search on the GIN index; a trigram fallback can be added as a toggle without a migration. |
| D32 | 2026-10-15 | Snippets come from `ts_headline` with private Unicode delimiters that the UI turns into `<mark>`; no HTML from the database is ever rendered | Transcript text can contain anything; this keeps highlighting safe. |
| D33 | 2026-10-15 | A saved view stores the filter object (without the page number) as JSON; `/views/[id]` redirects to `/search?…&view=id`. Views are shared with the team by default; the owner or an admin can delete them | The URL is the single source of truth for a search, so a view is just a bookmark of it. |
| D34 | 2026-10-15 | Tag filters on transcript lines match lines covered by a tagged highlight; participant filters apply to the source's participants, not the speaker of a line | Lines have no tags of their own; this is the most useful reading of "filter by tag" when looking at transcript text. |
| D35 | 2026-10-15 | Pages call `requirePageUser()` (redirects to `/login`); actions and route handlers call `requireUser()` (throws, mapped to `{ok:false}` or 401). Route handlers check the user before looking anything up | Next renders a page in parallel with its layout, so a layout-only redirect still lets the page throw; anonymous API callers must not learn whether an id exists. |
| D36 | 2026-10-15 | Login identifier is any non-empty string; only user creation validates email format | The seeded dev users are `name@local`, and the database lookup is the real check. |
| D37 | 2026-10-15 | The login form keeps the typed email in the action state | React resets a form after a server action completes; a wrong password should only ask for the password again. |
| D38 | 2026-10-15 | Production runs as one Compose stack: `app` (standalone Next image), `db` (postgres:17), plus tool profiles `migrate` (build-stage image with the Prisma CLI) and `backup` (pg_dump + tar of uploads, 14-day rotation). Caddy on the host terminates TLS with `request_body max_size 2GB` | One VM, no orchestration; migrations run explicitly per release; the upload limit must match in Caddy and the app. |
| D39 | 2026-10-15 | The first admin is created from the shell with `scripts/create-user.ts`; later users from the Users page. Setting a password signs that user out everywhere | No self sign-up (spec); a password reset should invalidate stolen sessions. |
| D40 | 2026-10-15 | `documentation/heymarvin-feature-gap.md` is the planning input for v2: it inventories Marvin's features from its site and help centre and marks each as built, partial, not built, scheduled by the spec, or excluded by the spec. AI features stay excluded until the team asks (spec) | Bruno judged v1 thin against Marvin and asked for an honest, sourced comparison before choosing what to build next. |
| D41 | 2026-10-15 | In-app transcription is now in scope (reverses the spec v0.1 exclusion). Engine choice (self-hosted Whisper vs. a transcription API) and diarization approach still to be decided | Bruno: "in app transcription would be great". Every recording should become a transcript without a detour through Teams, Zoom or Krisp. |
| D42 | 2026-10-15 | Open: auto-tagging design (suggestion-only with a review queue is the proposed shape) and a browsable, tree-like way to explore highlights, which Bruno wants as the distinctive part of this product | Discussion on 2026-10-15; no build yet. |
| D43 | 2026-10-15 | Highlight explorer: built for stakeholders browsing (not researchers synthesising); default pivot is Projects (product area → project → source → speaker), with Tags and People as alternative pivots; user-made Themes (a statement plus dragged-in highlights) are part of the first version and are the implementation of the spec's v2 "insights" | Bruno's answers on 2026-10-15. Themes-in-the-tree replaces a heavy report editor as the way findings are expressed. |
| D44 | 2026-10-15 | Auto-tagging will be suggestion-only with a review queue: suggested tags on a highlight, and SUGGESTED highlights proposed for a new transcript, both accepted by a person; only active global tags, no auto-created tags; Claude via API as the model | Bruno approved the proposed shape ("Ok"). |
| D45 | 2026-10-15 | The unused `Insight`/`InsightHighlight` tables are replaced by `Theme`/`ThemeHighlight`: a theme is a finding stated as a sentence, with description, confidence, product area, an optional parent theme (nesting) and ordered highlights from any project | Themes are the spec's v2 "insights" expressed as nodes in the explorer tree (D43) instead of a report editor. |
| D46 | 2026-10-15 | Any signed-in user can create a theme and add visible highlights to it; only the theme's creator or a global admin can delete it. Deleting a theme keeps its highlights and moves sub-themes up one level | Stakeholders are the first users of the explorer; building a theme is how they participate. |
| D47 | 2026-10-15 | Explorer layout: three panes (tree, list, detail), four pivots over the same highlights (Projects: area → project → source → speaker; Tags: group → tag; People: segment → company → participant; Themes: nested), node addressed by a compact URL key (`project:<id>`, `speaker:<sourceId>:<name>`…), keyboard j/k, drag-and-drop of highlight cards onto theme nodes with an "Add to theme" picker as the fallback. Detail pane fetches transcript context with a server action so navigation stays client-side. `/` now opens `/explore` | Bruno's answers (D43). The URL carries pivot, node and selected highlight so any view can be shared. |
| D48 | 2026-10-15 | The schema now declares what the hand-written search migration created: `@default(dbgenerated("<stored expression>"))` on the two generated `search` columns, `@@index([search], type: Gin)` and the trigram index with `ops: raw("gin_trgm_ops")`. `prisma migrate diff` is empty. New migrations are still created with `--create-only` and read before `migrate deploy` | The themes migration was generated with DROP INDEX / DROP DEFAULT for those columns, ran non-transactionally and dropped the GIN indexes before failing. The fixed migration is idempotent and recreates them. |
| D49 | 2026-10-15 | The explorer lives in its own route group with its own top bar (brand, keyword search, "Repository" link, sign-out) and no repository sidebar. The keyword search uses the same Postgres full-text query as `/search` and narrows the tree counts, the list and the total together | Bruno: stakeholders should see a browsing surface, not the researcher's repository navigation; search belongs at the top of it. |
| D50 | 2026-10-18 | A read-only static demo of the explorer lives in `demo/` (Vite + React, no server) and is published to GitHub Pages from the `gh-pages` branch by `scripts/publish-demo.sh` (the GitHub token here lacks the `workflow` scope needed to push a Pages workflow; a workflow can replace the script later). Its data is `demo/public/data.json`, exported by `scripts/export-demo-data.ts` from the seeded database; the exporter refuses to run unless the fixture is the synthetic mirror and every project carries a fixture id, and it skips RESTRICTED projects. Themes in the demo are keyword-built examples. The repository was made public for this, since the account's plan allows Pages only on public repositories | Bruno asked to put the explorer on GitHub Pages with mock data only. GitHub Pages cannot run the Next.js app, so the demo re-implements browsing client-side on the exported JSON and reuses the pure helpers in `src/lib`. |
| D51 | 2026-10-18 | The GitHub repository is renamed `exidium/researchRepo` (GitHub redirects the old name); the Pages site is `exidium.github.io/researchRepo`. The static site is now a read-only copy of the whole repository UI (explorer, projects, sources with highlighted transcripts, participants, tags, search), routed by URL hash so deep links work on Pages. The local folder keeps its old name until Bruno renames it | Bruno: "don't call it MarvinDemo, call it researchRepo", and he wants to navigate the other pages online. |
