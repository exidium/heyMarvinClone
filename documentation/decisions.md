# Decision log

Every non-obvious decision made while building the research repository, newest at the bottom. Each entry says what was decided and why. Spec reference: "Internal Research Repository: Spec v0.1" (Oct 15, 2026).

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-10-15 | Project lives at `~/Projects/heyMarvinClone`; Personal project; private GitHub repo `exidium/heyMarvinClone` | Bruno's choice. The Google Drive project convention path does not exist on this Mac. |
| D2 | 2026-10-15 | Next.js 16 app router + TypeScript; Prisma 7 as ORM (not Drizzle). Prisma pinned to `^7.10` because npm `latest` is an 8.0 release candidate | Same stack as the sibling project `theyDoClone`; known patterns; one codebase for frontend and API. |
| D3 | 2026-10-15 | Tailwind 4 + shadcn/ui (base-nova, Base UI), zod, nuqs, vitest, playwright | Copied from the sibling project so the two apps feel and build the same way. |
| D4 | 2026-10-15 | Local development uses Homebrew Postgres 17 (database `research`). Docker Compose is only for the Hetzner deployment | Docker is not installed on the dev Mac. |
| D5 | 2026-10-15 | Highlights anchor to `(segmentId, characterOffset)` pairs, never to offsets in the whole transcript | Spec requirement: fixing a typo in one line must not shift highlights elsewhere. |
| D6 | 2026-10-15 | The transcript editor forbids splitting, merging or deleting segments in v1. Only text and speaker edits are allowed | Keeps highlight anchors stable; split/merge is the hardest edge case and not needed for v1. |
| D7 | 2026-10-15 | Search uses Postgres full-text search: generated `tsvector` columns on Segment and Highlight with GIN indexes, `websearch_to_tsquery`, `ts_headline`, queried via Prisma `$queryRaw`. `pg_trgm` index as an ILIKE fallback for exact phrases and non-English text | Spec says built-in FTS covers v1. Prisma's own `search` filter cannot rank or combine with the four-table filters. |
| D8 | 2026-10-15 | Seed data is a generated **synthetic** mirror in `fixtures/mirror/`, in the same folder and JSON shape as the Dovetail mirror, plus an importer that reads that shape | Bruno asked for mock data, not the confidential ADI export. The same importer can ingest the real mirror later by pointing `MIRROR_DIR` at it; real content never enters the repo. |
| D9 | 2026-10-15 | The auth and role seam (`getCurrentUser`, `requireProjectRole`, `projectAction`) exists from the first milestone; real email+password login is the last milestone | Spec: login is one of the last things. Role checks must not be retrofitted into every action later. |
| D10 | 2026-10-15 | Files are stored on server disk under `UPLOAD_DIR/sources/<sourceId>/`. The original transcript file is kept. Recordings are stored as uploaded; no ffmpeg transcoding in v1 | Spec. ffmpeg is only needed for v2 clips and is not installed locally. |
| D11 | 2026-10-15 | Tags are global. `TagGroup` is its own table so groups can be renamed and reordered. Tag names are unique case-insensitively | Spec: "manage the global tag list: groups, rename, merge, archive". |
| D12 | 2026-10-15 | No `proxy.ts` (the Next 16 replacement for middleware) in v1 | Next 16 buffers request bodies through the proxy and silently truncates them at 10 MB, which would corrupt uploads. Auth gating lives in the app layout and the action seam instead. |
| D13 | 2026-10-15 | Uploads are raw-body `PUT` route handlers that stream to disk through a byte limiter. Never server actions (1 MB body cap) or `request.formData()` (buffers the whole file in memory) | Recordings can be gigabytes. |
| D14 | 2026-10-15 | `cacheComponents` stays off. Pages are dynamic. `revalidatePath` runs after CRUD mutations but never during per-segment transcript saves | The app is per-user and dynamic; a re-render while typing would be disruptive. |
| D15 | 2026-10-15 | Permissions: `User.isAdmin` manages users, tag groups, tag rename/merge/archive and deletions. Any editor can create a tag while highlighting. OPEN projects give everyone VIEWER. RESTRICTED projects are hidden from lists and search unless the user is a member. A project's owner is ADMIN of that project | Spec roles table plus the open question answers: admin deletes participant data; tag list owned by admin, tag creation by user type. |
| D16 | 2026-10-15 | Search tag filter is ANY-of by default with an ALL toggle. Product area is free text with autocomplete, not an enum | Simple and matches Dovetail habits; an enum can come later if the list stabilises. |
| D17 | 2026-10-15 | Highlight colour comes from the tag group of its first tag (neutral fallback). Overlapping highlights are allowed and render nested | Dovetail-like readability. |
| D18 | 2026-10-15 | VTT and SRT cues are coalesced into utterance-sized segments (same speaker, gap under 2 s, until a sentence ends and about 200 characters). DOCX and Dovetail paragraphs are not coalesced | Per-cue segments of a few words make highlighting painful. |
| D19 | 2026-10-15 | A highlight whose text is deleted entirely becomes `ORPHANED` (kept, shown greyed in the side panel), never silently dropped. Undo restores it | Evidence must not vanish because of a typo fix. |
| D20 | 2026-10-15 | Re-uploading a transcript is blocked once the source has highlights; delete and recreate the source instead | A re-parse would replace all segments and orphan every highlight. |
| D21 | 2026-10-15 | The `AUTH_DISABLED` dev seam refuses to run when `NODE_ENV=production`. Sessions are opaque tokens (sha256 stored) in an HttpOnly cookie, 30 days; passwords hashed with argon2 | Safety and simplicity; the seam can be swapped for company SSO later. |
